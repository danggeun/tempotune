# Phase 6 — UI/UX 감사: 의도 복원과 제안 (2026-09-05)

> 원칙: 고치기 전에 읽는다. 지금 화면의 모든 디테일은 v1 커밋 50개 안에서 내려진 결정이다.
> 이 문서는 (1) 그 결정의 의도를 복원하고, (2) 연습 중인 연주자의 실제 상황에서 화면을 다시 보고, (3) 의도를 지키는 범위에서만 바꿀 것을 제안한다.
> 코드 변경은 §5 의 승인 뒤에만.

## 1. 사용 상황 — 이 앱은 어디에 놓여 있는가

| 순간 | 폰의 위치 | 손 | 시선 거리 | 화면에 바라는 것 |
|---|---|---|---|---|
| **조율** (세션 첫 1–2분) | 보면대 위 또는 무릎 | 한 손은 악기, 한 손은 펙/미세조정 | 30–50 cm | 음이름 + 얼마나 벗어났는지, 즉각 반응 |
| **연습 중 힐끗** (세션의 90%) | 보면대 위, 팔 길이 밖 | 둘 다 악기 | 60–90 cm | 박자(눈으로 확인), 음정 트레이스가 초록 띠 안에 있나. **조작 없음** |
| **조작** (BPM 바꾸기, REC 켜기) | 그대로 두고 손 뻗음 | 한 손, 활을 든 채 | 40–60 cm | 큰 타겟, 한 번의 탭, 오조작 시 되돌리기 |
| **되듣기** (연습 후) | 손에 들고 앉아서 | 둘 다 자유 | 25–35 cm | 정밀 조작 OK, 정보 밀도 OK |

→ 메인 화면(튜너·메트로놈)은 **원거리·힐끗·한 손** 화면이고, 메뉴·설정·편집기는 **근거리·앉아서·두 손** 화면이다. 같은 앱이지만 두 종류의 화면이며, 기준을 따로 적용해야 한다. 현재 디자인은 이미 이 구분을 따르고 있다(튜너 음이름 96px 급, 편집기 텍스트 11–13px). 이 구분을 흐리는 변경은 하지 않는다.

### 3.1 결함 — 의도와 어긋나거나 접근성 기준 미달

| # | 발견 | 증거 | 왜 문제인가 |
|---|---|---|---|
| D1 | **다크 모드 토스트가 배경에 묻힌다** | 토스트 `#111` 위 흰 글자, 다크 배경 `#0f0f0f` — 대비 1.05:1 (메뉴 다크 스크린샷의 "녹음 완료") | "삭제됨 · 실행 취소" 같은 되돌리기 안내를 못 본다. 라이트에서는 검정 필이 의도(대비)인데 다크에서 그 의도가 사라짐 |

### 3.2 의도는 맞지만 상황(거리·손)에서 더 좋아질 수 있는 것

| # | 발견 | 제안 방향 |
|---|---|---|
| S1 | 튜너 헤더의 상태 점(ai-dot)이 Phase 2 이후 빈 자리 | `66e7159` 의 "점으로 말한다"를 이어 **오디오 상태 점**으로: 마이크 켜짐 = 은은한 초록, 중단/재시도 필요 = 앰버 펄스. 텍스트 없음 |
| S2 | A-B 반복이 A 지점에서 바로 시작 | 연주자는 활을 준비할 시간이 필요. 반복 버튼 상태 순환 꺼짐 → 켜짐 → 켜짐·1초 앞에서 (라벨 "꺼짐 / 켜짐 / 1s 앞") |
| S3 | 속도 슬라이더는 근거리 정밀 조작 | 슬라이더는 두고, **값 라벨(1.0×) 탭**으로 0.5 / 0.7 / 0.85 / 1.0 순환. 녹음별 마지막 속도 기억 |
| S4 | 녹음 목록에 편집 상태가 안 보임 | 이름 아래 muted 모노로 `북마크 3 · A-B` (있을 때만). 정보는 있는 것만 |
| S5 | 30일 자동 삭제가 예고 없음 (설계서 C4 "삭제 전 안내" 미구현) | 목록 항목에 `3일 후 삭제` 를 남은 7일부터만 표시 |
| S6 | 페이지 전이가 화면마다 다름 (메뉴 .25 s 슬라이드, 설정 클래스 전이, 편집기 `display:flex` 즉시) | 편집기 **진입**만 메뉴와 같은 .2 s 페이드. 편집기 → 메뉴 복귀는 의도대로 즉시 |
| S7 | 드럼 피커(78×28)를 헤더에서 드래그 | 이미 작동하지만 히트 영역을 위아래로 12 px 확장 |

### 3.3 확인했고 **바꾸지 않는** 것 (의도 존중)

- 튜너 cents 숫자 20 px: 조율 순간은 근거리. 트레이스와 초록 띠가 원거리 정보. 유지.
- 벗어남에 색 없음(흰 트레이스·흰 바늘): 의도. 유지.
- 태블릿 메트로 카드 아래 빈 공간: "추가하지 않는다". 유지.
- 메트로 접힘 타이밍, 라이트 팔레트, 섹션 제목, 단계 버튼 틴트: 유지.
- 파형 확대(Phase 4 리뷰 제안): 더블탭은 발견되지 않고, 확대 상태는 언어 밖의 UI 를 부른다. **실사용 후** 판단. 보류.
- 북마크 한 단어 라벨: 입력 UI(prompt)가 앱 안에 하나 더 생긴다. 보류.
- 시스템 글꼴 크기 대응(px → rem): 튜너 레이아웃이 px 로 고정된 건 의도로 보임(카드 안 배치). 전환은 큰 변경. **사용자 결정 필요**.
- 햅틱: 취향. **사용자 결정 필요**.

## 5. 진행 방식

1. 승인받은 항목만 구현. A 그룹은 한 커밋, B 그룹은 항목별 커밋.
2. 각 항목 전후 스크린샷을 이 문서 옆 `test-assets/screens/phase6/` 에 남긴다(의도된 변경의 기록).
3. 기준선 스크린샷은 A4/A5/A7/B1/B4 처럼 정적 화면이 바뀌는 항목만 갱신.
4. 완료 후 UX 관점 독립 리뷰 → 반영.
